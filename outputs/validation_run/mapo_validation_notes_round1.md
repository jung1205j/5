# 마포구 카페 입소문 시뮬레이션 — 1차 검증 정리본

**전달 대상:** 준안  
**검증 라운드:** 1  
**검증 대상:** 마포구 전체 16개 행정동  
**설정:** `weights_v2`, 시드 5회 반복

## 1. 검증 수치 및 결과

- 각 시드별로 16개 동의 시뮬레이션 `visitors`를 집계하고, 실제 카페 매출액과 Spearman 순위상관계수를 계산함.
- 시드별 상관계수: -0.6018, -0.4415, -0.6088, -0.4118, -0.5565.
- 시드별 상관계수 평균: **-0.5241** (표준편차 **0.0918**).
- 동별 **5개 시드 평균 visitors**와 실제 매출액의 Spearman 상관계수: **-0.6441** (p=0.0071). 팀 공유용 반올림 값: **-0.64**.
- 참고: 5개 시드 평균 visitors vs 실제 점포 수: **-0.6171** (p=0.0109), vs 2025년 분기 평균 유동인구: **-0.0382** (p=0.8882).

## 2. 실제 순위와 불일치하는 지역

- **과소평가(외부 방문객 영향이 큰 상권):** 서교동·상암동·연남동·합정동.
- **과대평가(거주민 중심 지역):** 염리동·용강동·아현동.
- 확인된 예시: 서교동 실제 매출 1위 vs 시뮬레이션 14위, 상암동 실제 매출 2위 vs 시뮬레이션 16위. 나머지 동은 최종 CSV에서 순위를 확인할 것.

**원인 가설:** 현 엔진은 거주민을 중심으로 입소문이 확산되므로, 외부 방문객·출퇴근 인구의 방문이 중요한 상권을 충분히 반영하지 못할 가능성이 있음. 이 설명은 현재 모델 구조와 관찰된 패턴에 근거한 가설이며, 수정 실험으로 검증할 예정.

## 4. 검증 루프

1. 동일한 `weights_v2` 설정으로 마포구 16개 동에 대해 시드 1~5를 각각 실행(총 80개 동-시드 결과).
2. 결과 JSON에서 동별 `visitors`를 수집하고, 동별 5개 시드 평균을 계산.
3. 동 코드를 기준으로 실제 카페 매출, 점포 수, 유동인구를 결합.
4. 평균 `visitors`와 실제 매출액 간 Spearman 순위상관계수 계산(높은 값이 높은 순위라는 방향을 맞춰 비교).
5. 실제 상권 순위와 시뮬레이션 순위가 크게 어긋난 동을 확인하고 원인 가설을 기록.
6. **다음 라운드:** 유동인구·직장인구를 시뮬레이션의 출발점과 방문 계산에 반영한 후, 같은 동·시드 수·비교 지표로 재검증. 변경 전후 상관계수와 동별 순위 오차를 비교.

## 5. 멘토 질문

1. 거주민 중심 입소문 모델에 유동인구·직장인구를 추가할 때, 외부 유입 인구를 **별도 에이전트/출발점**으로 생성하는 방식과 기존 주민의 **주간 이동 확률**을 조정하는 방식 중 무엇이 더 적절할까요? 중복 집계는 어떻게 피할 수 있을까요?
2. 시뮬레이션 `visitors`와 실제 행정동 카페 **총매출**의 순위상관만으로 타당성을 평가해도 될까요? 점포 수 차이 등을 고려한 **점포당 매출·방문자 수**, 동별 순위 오차 등의 보조 지표를 함께 사용하는 것이 적절할까요?
