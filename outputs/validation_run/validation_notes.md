# 마포구 카페 입소문 시뮬레이션 — MVP 1차 검증 메모

**전달 대상:** 준안  
**검증 라운드:** 1  
**검증 대상:** 마포구 전체 16개 행정동  
**설정:** `weights_v2`, 시드 5회 반복

## 1. 검증 수치 및 결과

- 각 시드별로 16개 동의 시뮬레이션 `visitors`를 집계하고, 실제 카페 매출액과 Spearman 순위상관계수를 계산함.
- 시드별 상관계수: -0.6018, -0.4415, -0.6088, -0.4118, -0.5565.
- 시드별 상관계수 평균: **-0.5241** (표준편차 **0.0918**).
- 동별 **5개 시드 평균 visitors**와 실제 매출액의 Spearman 상관계수: **-0.6441** (p=0.0071). 팀 공유용 반올림 값: **-0.64**.
- 참고: 5개 시드 평균 visitors vs 실제 점포 수: **-0.6171** (p=0.0109), vs 2025년 분기 평균 유동인구: **-0.0382** (p=0.8882).

## 2. 실제 순위와 불일치하는 지역

- **과소평가(외부 방문객 영향이 큰 상권):** 서교동·상암동·연남동·합정동.
- **과대평가(거주민 중심 지역):** 염리동·용강동·아현동.
- 확인된 예시: 서교동 실제 매출 1위 vs 시뮬레이션 14위, 상암동 실제 매출 2위 vs 시뮬레이션 16위. 나머지 동은 최종 CSV에서 순위를 확인할 것.

**원인 가설:** 현 엔진은 거주민을 중심으로 입소문이 확산되므로, 외부 방문객·출퇴근 인구의 방문이 중요한 상권을 충분히 반영하지 못할 가능성이 있음. 이 설명은 현재 모델 구조와 관찰된 패턴에 근거한 가설이며, 수정 실험으로 검증할 예정.

## 3. 데이터 출처 및 기준 기간

| 자료 | 출처 및 활용 | 이번 검증에서 사용한 기준 |
|---|---|---|
| 한국 페르소나 | [NVIDIA Nemotron-Personas-Korea](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Korea) 기반 한국 페르소나. 마포구 가상 시민 약 2,000명 구성 | 합성 페르소나 데이터이며 실제 인구 관측 연도와 직접 대응하지 않음. 원천 통계 기준 연도는 확인되지 않음 |
| 행정동 경계 | 팀 저장소 `data_prep/mapo_dong.geojson` (마포구 16개 행정동 경계). 시민의 동별 배정 및 동 내부 좌표 생성 | 파일에 경계 기준 연도·원본 제공기관이 명시되어 있지 않아 특정 연도 확정 불가 |
| 카페 추정매출 | 서울시 상권분석서비스 행정동별 추정매출 자료. 동별 매출 순위 산출 | **2025년 1~4분기 매출 합산** (기존 분석 작업 기록 기준) |
| 상권 점포 수·개폐업 | 서울시 상권분석서비스 관련 점포 집계 자료. 동별 점포 수와 개·폐업 현황 비교 | 사용한 가공 집계표에는 기준 분기가 남아 있지 않아 정확한 추출 시점은 미확인 |
| 유동인구 | 서울 열린데이터광장 `서울시 상권분석서비스(길단위인구-행정동)`의 `총_유동인구_수` | **2025년 1~4분기**, 동별 네 분기 수치의 산술평균 (연간 합계 아님) |

참고: [NVIDIA 원본 데이터셋](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Korea) · [서울시 상권분석서비스](https://golmok.seoul.go.kr/main.do)

**기간 관련 메모:** 매출과 유동인구는 2025년 자료를 사용했다. 점포 수 집계의 기준 시점과 행정동 경계 파일의 제작 연도는 현재 보관된 가공 파일만으로 특정할 수 없어 확정값을 적지 않았다. 이번 MVP 1차 검증에서는 이를 한계로 기록하고, 다음 검증 때 원본 추출 시점을 함께 보관할 계획이다.

**지표 구분:** `cafe_count`는 인허가 기반 생존 분석 표본 수이고, `store_count`는 상권 점포 수로 서로 다른 지표다. 유동인구도 실제 카페 방문자 수와 동일한 값은 아니다.

## 4. 검증 루프

1. 동일한 `weights_v2` 설정으로 마포구 16개 동에 대해 시드 1~5를 각각 실행(총 80개 동-시드 결과).
2. 결과 JSON에서 동별 `visitors`를 수집하고, 동별 5개 시드 평균을 계산.
3. 동 코드를 기준으로 실제 카페 매출, 점포 수, 유동인구를 결합.
4. 평균 `visitors`와 실제 매출액 간 Spearman 순위상관계수 계산(높은 값이 높은 순위라는 방향을 맞춰 비교).
5. 실제 상권 순위와 시뮬레이션 순위가 크게 어긋난 동을 확인하고 원인 가설을 기록.
6. **다음 라운드:** 유동인구·직장인구를 시뮬레이션의 출발점과 방문 계산에 반영한 후, 같은 동·시드 수·비교 지표로 재검증. 변경 전후 상관계수와 동별 순위 오차를 비교.

## 5. 멘토 질문

1. 유동인구와 직장인구를 추가할 때, 실제 인구가 중복 계산되지 않도록 어떤 방식으로 반영하는 게 좋을까요?
2. 현재는 방문자 수와 실제 매출 순위의 상관계수를 비교했는데, MVP 검증에서 함께 보면 좋은 지표가 있을까요?
